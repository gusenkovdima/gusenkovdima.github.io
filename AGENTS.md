## Обязательное общее правило: пароли и интерактивный TTY

Для любого разрабатываемого или выдаваемого AI-операторского Bash/WSL/SSH/Python скрипта (в том числе разового install/backup/deploy) действует следующий контракт:

1. **До** запроса явно напечатать в `/dev/tty`: этап, удалённую/локальную систему, точное имя пароля или ключа, откуда взять, что символы скрыты, и необходимость Enter. Для `sudo` — явный `sudo -p '[sudo] <system> password: '`. Нельзя заставлять пользователя угадывать, что требует терминал.
2. Печатать prompt непосредственно **до** `read -r -s`/`getpass`. Скрыт только ввод, не приглашение; если TTY отсутствует — STOP. Во время интерактивного `ssh -tt` **не использовать** `| tee/tr/grep/sed`, `$(ssh ...)`, буферизованные обёртки. Подключать `ssh -tt ... </dev/tty` прямо к терминалу.
3. Если SSH/sudo может читать stdin, не передавать весь WSL script heredoc в `bash` с наследуемым stdin: он может поглотить остаток и выдать ложный `exit=0`. Использовать дочерний `bash -c` или проверенный локальный файл; конечный `command_exit_code` и PASS должны отражать **всю** операцию.
4. `set +x`; секреты не помещать в Git, логи, чат, CLI args, URL или обычные файлы; runtime secret только в private tmpfs при необходимости (root `0700`/`0600`, noclobber, собственный cleanup). Разные машины/ключи — отдельные подписанные запросы.
5. При ошибке — безопасная фаза и реальный код, без приватного stderr, но и без бессодержательного «что-то сломалось». После неопределённого S3 PUT/другой irreversible write — STOP **без retry**; сохранять артефакты, не объявлять успех по предварительной проверке.
6. Для новых privileged/secret операторов — PTY-тесты на **синтетических данных**: prompt виден до ввода, секрет не отражается, EOF/Ctrl+C и исключения безопасны.

**Подробная спецификация:** [Общий стандарт interactive-secrets](https://github.com/gusenkovdima/personal-ai-playbook/blob/main/procedures/interactive-secrets/README.md).

Эти правила не заменяют README, собственные workflows, согласование опасных изменений, privacy и ограничения доступа. Изменение только документационное, не разрешает production запуск или merge.
